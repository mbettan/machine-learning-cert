Overview & Wiring Paths

Definition: The Claude Agent SDK (TypeScript @anthropic-ai/claude-agent-sdk · Python claude-agent-sdk, which replaces claude-code-sdk) packages the Claude Code agent harness as a library: the agent loop, built-in tools, permissions, hooks, subagents, sessions and MCP, running inside your process. This guide covers the SDK API and the architecture patterns you build with it: loops, coordinator–subagent orchestration, deterministic enforcement, session state, tool error design, escalation, error propagation, long-context management and provenance.

Three ways to wire an agent:

Wiring pathWho runs the loopYou ownPick when
Raw Messages API loopYour codeTool execution, stop_reason handling, state, retries, compactionFull control, minimal dependencies
Claude Agent SDKSDK in your processHosting, filesystem isolation, storageYou want Claude Code's tools, hooks, subagents and sessions in your own infrastructure
Claude Managed AgentsAnthropic server-sideAgent config, custom tool handlers, session lifecycleLong-running hosted sandbox sessions without running containers yourself

Mental model

The model decides (which tool, which subagent, when to stop); the harness enforces (permissions, hooks, budgets). Anything that must hold 100% of the time belongs in code (hooks, tool scoping, prerequisite gates), never only in the prompt.

Scope note

Claude Code configuration (permission modes, CLAUDE.md, skills, plugins, CLI flags) lives in the Claude Code guide. MCP protocol internals live in the MCP guide.

1. The Agentic Loop & stop_reason

Raw Messages API loop (what the SDK does for you):

01

Call

Send messages + tools to Claude.

02

Inspect

Read stop_reason on the response.

03

If "tool_use"

Execute every tool_use block, append the assistant turn, then append one user turn containing a tool_result block per call (matched by tool_use_id). Go to 1.

04

If "end_turn"

The model is done. Use the final text.

stop_reasonMeaningLoop action
tool_useClaude wants tools runExecute, append tool_results, call again
end_turnNatural completionStop; return the answer
max_tokensHit your max_tokens cap mid-responseRaise the cap or continue the response; output is truncated
pause_turnA server-tool loop hit its iteration limitSend the assistant content back unchanged to let Claude continue
refusalClaude declinedHandle explicitly (read stop_details, fallback model or human)
stop_sequenceOne of your stop_sequences firedRead stop_sequence
model_context_window_exceededResponse filled the context windowTreat as truncated; compact or split the task

Decision rule

The loop's termination signal is stop_reason, not the text. Continue on tool_use; stop on end_turn; handle the rest explicitly.

Exam traps (loop anti-patterns)

(1) parsing natural language ("I'm done", "task complete") to decide termination; (2) treating "the response contains text" as completion (Claude often writes text and calls tools in the same turn); (3) using an arbitrary iteration cap as the primary stop condition (keep a cap only as a safety bound); (4) dropping tool results instead of appending them, so the model cannot reason about what happened.

Model-driven vs pre-configured: In an agent loop Claude chooses the next tool from context. A fixed decision tree or hard-coded tool sequence is a workflow, not an agent; use it only when the order is known in advance (see §3).

The SDK version of the loop: query() runs the loop and streams messages (AssistantMessage, ResultMessage, …). Check ResultMessage.subtype first:

ResultMessage.subtypeWhat happenedresult present?
successFinished normallyYes
error_max_turnsHit max_turns / maxTurnsNo
error_max_budget_usdHit max_budget_usd / maxBudgetUsd (subagent spend counts toward the cap)No
error_during_executionLoop interrupted (cancelled request, crash)No
error_max_structured_output_retriesNo schema-valid structured output within the retry limitNo
  • Every result carries session_id, total_cost_usd, usage, num_turns, so you can resume even after an error. The result also has a stop_reason (end_turn, max_tokens, refusal, …).
  • A single-shot query() raises after yielding an error result: wrap the loop in try if you need to continue (for example, resume with a higher max_turns).

2. Agent SDK Core API

  • query(prompt, options) vs ClaudeSDKClient:
    • query() starts a fresh session per call unless you pass continue_conversation=True (continue: true in TS), resume=session_id (from ResultMessage.session_id), or resume=session_id, fork_session=True (forkSession: true) to branch history into a new session ID. Fork trap: fork_session branches the conversation transcript only, not the filesystem. Pair with enable_file_checkpointing=True + rewind_files(user_message_id) to restore disk state.
    • ClaudeSDKClient (Python async with ClaudeSDKClient(options) as client:): reuses one session across multiple await client.query(...) + client.receive_response() turns and supports await client.interrupt() (drain buffered messages up to the interrupted turn's ResultMessage before sending the next query). TypeScript has no ClaudeSDKClient class; call methods on the Query object returned by query().

setting_sources / settingSources ("user" | "project" | "local"):

  • Omitted (default) → loads user, project and local settings, CLAUDE.md, skills, agents and hooks, just like the interactive CLI. *(Exception: if top-level skills is passed while setting_sources is omitted, only user and project load.)*
  • [] (empty list) → disables user, project and local filesystem settings and CLAUDE.md. Multi-tenant trap — what setting_sources=[] still loads: (1) managed policy settings, (2) ~/.claude.json global state (isolate via CLAUDE_CONFIG_DIR in env), (3) auto memory MEMORY.md (disable with CLAUDE_CODE_DISABLE_AUTO_MEMORY="1" or autoMemoryEnabled: false), and (4) claude.ai MCP connectors (mcp_servers={} does not suppress them; pass strict_mcp_config=True / strictMcpConfig: true).
Option (Python / TS)What it controls & critical SDK traps

allowed_tools / allowedToolsPre-approves matching calls; unlisted tools stay in context and fall through to permission_mode / can_use_tool. No effect in bypassPermissions.
disallowed_tools / disallowedToolsBare names ("Bash") remove the tool from context; scoped rules ("Bash(rm *)") keep the tool and deny matching calls in every mode, including bypassPermissions. File-write rules must use Edit(//abs/path) (Write(...) never matches).

3. Coordinator–Subagent Orchestration & Decomposition

Hub-and-spoke: one coordinator decomposes the task, decides which subagents to invoke, passes each one the context it needs, aggregates results and handles errors. Subagents never talk to each other directly; all routing goes through the coordinator (observability, consistent error handling, controlled information flow).

Coordinator responsibilityDoAvoid
SelectPick subagents based on what the query needs (simple question → one agent)Always running the full pipeline for every request
PartitionGive each subagent a distinct subtopic or source typeOverlapping scopes → duplicated work and conflicting findings
DecomposeCover the whole question; check the decomposition against the original goalOverly narrow subtasks that silently drop parts of a broad topic
InstructState goals, scope and quality criteriaStep-by-step procedures that stop subagents from adapting
RefineEvaluate the synthesis for gaps, re-delegate targeted queries, re-synthesizeAccepting the first synthesis even when coverage is thin

Choosing a decomposition pattern:

PatternUse whenExample
Prompt chaining (fixed sequential pipeline)Steps and order are known in advance; predictable multi-aspect workReview each file individually → separate cross-file integration pass
Dynamic / adaptive decompositionOpen-ended investigation; next steps depend on findings"Add tests to a legacy codebase": map structure → find high-impact areas → prioritized plan that adapts as dependencies appear
Parallel fan-outSubtasks are independentSearch, document analysis and data lookup at the same time

Exam trap — attention dilution

One giant prompt reviewing 30 files at once gives shallow, inconsistent findings. Split into per-file local passes plus one cross-file integration pass.

4. Subagent Invocation, AgentDefinition & Context Passing

Python — coordinator with an AgentDefinition subagent 
from claude_agent_sdk import query, ClaudeAgentOptions, AgentDefinition

options = ClaudeAgentOptions(
    allowed_tools=["Read", "Grep", "Glob", "Agent"],   # the coordinator needs the Agent tool
    agents={
        "code-reviewer": AgentDefinition(
            description="Security and quality review. Use for code review tasks.",  # WHEN to delegate
            prompt="You are a code review specialist...",                           # subagent system prompt
            tools=["Read", "Grep", "Glob"],                                         # least privilege
            model="sonnet",
        ),
    },
)
  • Spawning mechanism: Claude spawns subagents through the Agent tool (legacy name Task, still accepted as an alias; older docs and exams say "Task tool"). The coordinator can only delegate if that tool is in context (with an explicit tools list, include "Agent"; a bare disallowed_tools entry removes it) and approved (docs examples also list "Agent" in allowed_tools, which only pre-approves calls).
  • AgentDefinition fields: description (required; tells the coordinator when to use it), prompt (required; system prompt), tools (omit = inherit all), disallowedTools, model ("sonnet", "opus", "haiku", "inherit", or full ID), skills, mcpServers, maxTurns, memory, background, effort, permissionMode, omitClaudeMd (TS).
  • Fan-out limits: spawn depth and concurrency are capped by CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH and CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS (verify current defaults).
A (non-fork) subagent receivesIt does not receive
Its own system prompt (AgentDefinition.prompt) + the Agent tool's prompt stringThe parent's conversation history or tool results
Project CLAUDE.md (via setting_sources, unless omitClaudeMd)The parent's system prompt
Its tool definitions (inherited or the tools subset)Skill content, unless listed in skills

Decision rule — context passing

The only channel from coordinator to subagent is the prompt string. Put everything the subagent needs in that prompt: complete prior findings, file paths, error messages, decisions. Use a structured format that separates content from metadata (source URL, document name, page, date) so attribution survives.

  • Return path: only the subagent's final message returns to the coordinator; intermediate tool output is discarded. Ask subagents to return structured results (or write artifacts to disk and return the path).
  • Parallel subagents: emit multiple Agent tool calls in a single coordinator response to run them concurrently. Spreading them across separate turns serializes the work.
  • Fork vs fresh subagent: a fork inherits the parent conversation; a normal subagent starts fresh. Use fresh subagents for isolation and independent review.

5. Hooks: Deterministic Enforcement vs Prompts

NeedMechanismWhy
A rule that must always hold (identity verified before refund, refund cap, no writes to .env)PreToolUse hook (or tool scoping / prerequisite gate in code)Prompts are probabilistic: a non-zero share of runs will skip or misread the instruction
Normalize or redact tool output before the model sees itPostToolUse hook (updatedToolOutput, additionalContext)One place to fix heterogeneous formats (Unix epoch vs ISO 8601, numeric status codes)
Style, tone, preferred approach, soft prioritiesSystem prompt / CLAUDE.mdGuidance; occasional deviation is acceptable
Python — PreToolUse refund guard registered with HookMatcher 
from claude_agent_sdk import ClaudeAgentOptions, HookMatcher

async def refund_guard(input_data, tool_use_id, context):
    amount = input_data["tool_input"].get("amount", 0)
    if amount > 500:
        return {"hookSpecificOutput": {
            "hookEventName": "PreToolUse",
            "permissionDecision": "deny",
            "permissionDecisionReason": "Refunds over $500 need a human: call escalate_to_human with a handoff summary."}}
    return {}   # empty dict = allow unchanged

options = ClaudeAgentOptions(hooks={"PreToolUse": [HookMatcher(matcher="mcp__billing__process_refund", hooks=[refund_guard])]})
  • Callback signature: (input_data, tool_use_id, context); input_data has tool_name, tool_input, hook_event_name (plus agent_id / agent_type inside subagents).
  • PreToolUse outputs (in hookSpecificOutput): permissionDecision = "allow" | "deny" | "ask" | "defer", permissionDecisionReason (sent to Claude), updatedInput (rewrite arguments). "defer" ends the turn with stop_reason: "tool_deferred" so you can resume later.
  • PostToolUse outputs: additionalContext (append to the tool result) and updatedToolOutput (replace the output before Claude sees it).
  • Precedence: across hooks and permission rules, deny > defer > ask > allow. One deny blocks the call.
  • Prerequisite gate pattern: keep state in your app (for example, "verified customer ID returned by get_customer"); a PreToolUse hook on process_refund denies until that state exists, with a reason that tells Claude which step to run first.
  • Deny + redirect: the permissionDecisionReason should name the alternative path (escalate, ask for ID), so the model recovers instead of retrying.

Exam trap

"Add a stronger instruction in the system prompt (MUST, ALWAYS)" is the wrong answer whenever the scenario needs guaranteed compliance (money, identity, safety). Use a hook or code-level gate.

6. Session State: Resume, Fork & Named Sessions

OperationSDKClaude Code CLIEffect
Continuecontinue_conversation=Trueclaude --continue (-c)Most recent session in the current directory; same session ID
Resumeresume=session_idclaude --resume <id-or-name> (-r), /resumeSpecific session; same ID; full prior context
Forkresume=id, fork_session=True (forkSession)--resume <id> --fork-session, /branchNew session ID with a copy of the history; original unchanged
Name—claude -n <name> / --name, /rename <name>Resume later with claude --resume <name>
  • Fork use case: from one shared analysis baseline, explore two divergent approaches (two testing strategies, two refactors) and compare, while the original stays resumable.
  • Fork is transcript-only: the filesystem is shared. Forks that edit files collide unless isolated (worktrees, checkpoints).

Decision rule — resume vs start fresh

Resume when prior context is still valid. If files changed since the analysis, tell the resumed session exactly which files changed for targeted re-analysis. If many prior tool results are stale, start a new session with a structured summary of the still-valid findings: stale tool output in history misleads the model more than a clean summary.

7. Structured Tool Errors (isError)

Mechanics (grounded): an MCP tool result can set isError: true; SDK in-process tools return {"content": [...], "is_error": True} (Python) or isError: true (TS). A handler error does not stop the agent loop: an uncaught exception becomes an error result carrying the raw message, while a caught error lets you compose a message Claude can act on.

Design convention (application level, not MCP spec fields): put a structured payload in the error content so the agent can decide what to do next.

JSON — structured tool error (application-level convention) 
{ "isError": true,
  "content": [{ "type": "text", "text": "{\"errorCategory\": \"transient\", \"isRetryable\": true, \"message\": \"Order service timed out after 10s\", \"attempted\": \"lookup_order(id=8812)\", \"suggestion\": \"Retry once; if it fails again, tell the customer and escalate\"}" }] }
errorCategoryExampleisRetryableAgent should
transientTimeout, 503, rate limittrueRetry with backoff (ideally locally inside the tool or subagent)
validationMalformed date, missing fieldfalse (until input fixed)Fix the input and call again, or ask the user
permissionCaller lacks accessfalseStop that path; escalate or use an authorized route
businessRefund exceeds policy, account frozenfalseExplain the policy to the user and offer the allowed alternative

Exam trap — access failure vs valid empty result

"No orders found" for a valid query is a successful result (isError false, results: []). A timeout is an error. Returning [] on a timeout makes the agent tell the customer "you have no orders": silent suppression. Returning a generic "Operation failed" hides whether a retry could work.

8. Tool Distribution, Scoping & tool_choice

  • Least tools per agent: give each subagent only the tools for its role (AgentDefinition.tools). More tools = more schema tokens and more mis-selection; tools from another role invite misuse (a synthesis agent with web search starts re-searching instead of synthesizing).
  • Scoped variants: instead of handing a broad tool to every agent, expose a narrow one where needed (for example, a read-only verify_claim for the synthesis agent while full search stays with the search agent). Route other cross-role needs back through the coordinator.
  • Replace generic tools with constrained ones when misuse is the risk (a fetch_order(order_id) tool instead of raw SQL access).

tool_choice (Messages API):

ValueBehaviorUse for
{"type": "auto"}Claude decides whether to call a tool (default when tools are provided)Normal agent turns
{"type": "any"}Must call some tool, Claude picks whichGuarantee a structured tool call when several output schemas exist
{"type": "tool", "name": "extract_metadata"}Must call that toolForce a mandatory first step (extract before enrich), then switch back to auto
{"type": "none"}No tool calls (default when no tools)Pure text turns

Exam traps

Forcing a tool every turn turns an agent into a fixed pipeline (it can never finish with end_turn text). Forced calls skip thinking. Manual extended thinking does not support any / tool, and some newer models reject them with a 400: use auto with strict tool definitions there (verify per model).

9. Escalation & Ambiguity Resolution

Escalate to a human when…Do not use as the trigger
The customer explicitly asks for a human → honor immediately, without investigating firstSentiment (frustration ≠ complexity; calm customers can have policy-gap cases)
Policy is silent or ambiguous for this request (exception, gap)Self-reported confidence scores from the model (poorly calibrated)
The agent cannot make meaningful progress (repeated failures, missing authority)"The case looks complex" without a concrete criterion
  • Write explicit criteria in the system prompt, with few-shot examples of escalate vs resolve.
  • Frustrated but simple: acknowledge the frustration and offer the fix; escalate if the customer repeats the request for a human.
  • Multi-concern requests: split the message into distinct issues (e.g. a refund and an address change), investigate each one (in parallel where independent) against the same verified customer context, then reply with one unified resolution that addresses every item, rather than answering only the first concern.
  • Ambiguous identity: if a lookup returns multiple matches, ask for another identifier; never pick by heuristic (most recent, first row).
  • Handoff summary: the human usually cannot see the transcript, so pass a structured summary: customer ID, issue, root cause, what was tried, amounts, recommended action.

10. Error Propagation in Multi-Agent Systems

Subagent rule: recover locally from transient failures (bounded retries); propagate only what you cannot resolve, as structured error context:

JSON — subagent partial-failure payload 
{ "status": "partial", "failureType": "timeout", "attempted": "search('EU AI Act fines 2025', source=news)",
  "partialResults": [ { "claim": "...", "source": "..." } ], "alternatives": ["retry later", "use regulator site"] }
Anti-patternWhy it failsFix
Silent suppression (return empty/success on failure)Coordinator treats missing data as "nothing exists"Mark the failure explicitly; keep partial results
Kill the whole workflow on one subagent failureThrows away good partial workContinue with what succeeded; annotate the gap
Generic status ("search unavailable")Coordinator can't choose retry vs alternative vs proceedFailure type + attempted query + partial results + alternatives
Infinite retry in the subagentBurns budget, hides an outageBounded retries, then propagate
  • Coverage annotations: the final synthesis states which findings are well supported and which areas have gaps because sources were unavailable.

12. Provenance & Multi-Source Synthesis

  • Claim→source mappings: subagents return each claim with its source URL or document name, the relevant excerpt, location (page/section) and publication or collection date. The synthesis agent must preserve and merge these mappings; summarizing without them loses attribution.
  • Conflicts: when credible sources disagree, report both values with their sources and annotate the conflict; don't silently pick one. Let the coordinator decide how to reconcile.
  • Dates prevent false contradictions: 2021 vs 2024 figures may both be right; require dates in structured outputs.
  • Report structure: separate well-established from contested findings; keep the original methodology context.
  • Match format to content: use tables for quantitative metrics, narrative paragraphs for event summaries, and bulleted lists for engineering notes rather than forcing a single layout.
JSON — claim→source mapping with a conflict 
{ "claim": "Segment revenue grew 12% YoY", "source": "https://example.com/10-K-2024", "excerpt": "…increased 12%…",
  "location": "p. 41", "published": "2025-02-14", "conflicts_with": [{ "source": "analyst note", "value": "9%", "published": "2024-11-02" }] }

13. Managed Agents

All Managed Agents endpoints require the beta header managed-agents-2026-04-01 (set automatically by client.beta.agents / environments / sessions).

PrimitiveEndpoint & mechanics
1. AgentPOST /v1/agents — versioned definition (model, system string — no CLAUDE.md hierarchy, tools, mcp_servers, skills). Built-in sandbox tools use {"type": "agent_toolset_20260401"} (in /workspace); custom tools ({"type": "custom", ...}) pause the session and emit agent.custom_tool_use until your backend posts user.custom_tool_result. Per-tool permission_policy (always_allow, always_ask, auto) gates execution via user.tool_confirmation.
2. EnvironmentPOST /v1/environments — Anthropic-managed cloud container (type: "cloud", networking: {"type": "limited"} allowlists) or self-hosted runner.
3. SessionPOST /v1/sessions — binds a pinned agent version + environment_id, mounted resources (file, github_repository, memory_store), vault_ids (Vaults inject MCP/API credentials into outbound requests outside the container so raw secrets never enter the sandbox), and a spend budget.
4. EventsPOST /v1/sessions/{id}/events & SSE /events/stream — user.message, agent.message, agent.custom_tool_use → user.custom_tool_result, user.tool_confirmation, session.status_idle with stop_reason.type == "end_turn".

Compliance trap

Managed Agents is stateful by design (conversation history, container state and outputs stored server-side) and cannot be used under a HIPAA BAA or Zero Data Retention (ZDR) agreement. For regulated PHI or ZDR-governed data, run the loop yourself (Agent SDK or Messages API) on an eligible configuration.

Self-Assessment Questions (Click to Reveal)

Q1. A coordinator's loop stops whenever the assistant text contains “done”. What is wrong, and what should drive termination?

Natural-language completion signals are unreliable: Claude often writes text and requests tools in the same turn. Continue while stop_reason == "tool_use" (execute every tool_use block and append matching tool_results); stop on "end_turn"; keep an iteration cap only as a safety bound.

Q2. A synthesis subagent keeps asking which sources the research phase used. Why, and how do you fix it?

Non-fork subagents start fresh: they do not receive the coordinator's history, tool results or system prompt. The Agent tool's prompt string is the only channel, so pass the complete findings in it with content separated from metadata (URL, document, page, date).

Q3. Why does a PreToolUse hook beat a capitalised system-prompt rule for a $500 refund cap?

Prompt compliance is probabilistic; a hook runs in code on every matching call. Return permissionDecision: "deny" with a permissionDecisionReason that redirects Claude to escalation. Precedence is deny > defer > ask > allow.

Q4. An order-lookup tool times out. Why is returning an empty list the wrong behaviour?

An empty list is a valid “no orders” result, so the agent would tell the customer they have none (silent suppression). Return an error result (isError: true) with a structured payload such as errorCategory: "transient" and isRetryable: true, plus what was attempted.

Q5. In the Agent SDK, what four things can still load even when you pass setting_sources=[]?

(1) Managed policy settings, (2) ~/.claude.json global state (isolate via CLAUDE_CONFIG_DIR), (3) auto memory MEMORY.md (disable via CLAUDE_CODE_DISABLE_AUTO_MEMORY="1"), and (4) claude.ai MCP connectors (suppress via strict_mcp_config=True).

Q6. In Claude Managed Agents, how do you run a proprietary tool inside your own VPC while keeping third-party MCP credentials out of the cloud container?

Declare the VPC tool as {"type": "custom", ...} on the Agent so the session pauses and emits agent.custom_tool_use (your VPC executes it and posts user.custom_tool_result), and attach a Vault via vault_ids on the Session so credentials are injected server-side outside the sandbox.

Q7. Two sources report 9% and 12% growth for the same metric. What should the synthesis report contain?

Both values, each with its source, excerpt, location and publication date, plus an explicit conflict annotation. Dates often explain the difference; never average or silently pick one.
