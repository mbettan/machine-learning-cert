Overview & Mental Model

Definition

Gemini Enterprise Agent Platform is the evolution of Vertex AI for building, scaling, governing, and optimizing production agents on Google Cloud. This guide covers the build, retrieve, run, and optimize half: choosing among Agent Studio, the Managed Agents API, and code-first ADK / open frameworks, hosting agents on Agent Runtime (formerly Agent Engine), managed Sessions, Memory Bank, Example Store, and the Code Execution sandbox, choosing between Agent Runtime, Cloud Run, and GKE, enterprise retrieval and MCP tooling, 2-step user simulation and environment simulation, Agent Registry observability, programmatic prompt optimization, and FinOps quota management.

Companion Architecture Guides

Cryptographic Agent Identity, IAM, Principal Access Boundary (PAB), VPC Service Controls, Model Armor, Sensitive Data Protection, and Agent Gateway policies live in Agent Platform Security & Governance. Code-level ADK patterns live in the ADK guide; cross-agent wire protocols and A2UI/AP2 in A2A & Interoperability; vendor-neutral RAG in RAG; Gemini 4 Argon and Model Garden in Gemini & Google Models.

Mental model — 5-part agent anatomy on Google Cloud

The model (Gemini 4 Argon, Gemini 3.8 Flash…) is the reasoning brain; the orchestration layer (ADK, LangGraph, Managed Agents harness, or Agent Studio) wires the Think → Act → Observe loop; Agent Runtime is the managed body keeping long-running tasks alive; Sessions are short-term working memory for one conversation while Memory Bank is consolidated long-term memory across conversations; MCP servers, retrieval services, and the Code Execution sandbox are the hands and library; Evaluation + Observability + Agent Optimizer form the continuous AgentOps quality flywheel.

Rule 0 — managed by default

Choose the most managed component that meets the requirement. Move down the stack (Managed Agents API / Agent Studio → Agent Runtime → Cloud Run → GKE) only for a concrete engineering need: custom orchestration code, hosting stateless Streamable HTTP MCP servers, non-Python stacks, GPUs/self-hosted open weights, or kernel-level isolation.

Naming, preview status and limits evolve

Product names, preview status, quotas, and regional availability change frequently. Items marked Preview are Pre-GA without GA SLAs. Verify current limits and pricing in official Google Cloud documentation before production commitment.

2. Agent Runtime & Production Tooling

Agent Runtime is a fully managed, opinionated compute runtime for stateful agents: sub-second cold starts, long-running and multi-day asynchronous workflows, optional min_instances for warm capacity, IAM and VPC Service Controls enforcement, private VPC/on-prem egress through a Private Service Connect (PSC) interface network attachment, cryptographic Agent Identity, and built-in integration with Sessions, Memory Bank, Example Store, Code Execution, A2A, and OpenTelemetry.

Framework & protocol support

  • First-class native integration: ADK (Python: adk deploy agent_engine or agents-cli; Go via adkgo; Java & TypeScript via containers)
  • SDK templates: LangChain, LangGraph, AG2, LlamaIndex Preview
  • Custom Python class: CrewAI or any custom class implementing query / async_query / stream_query
  • A2A agent hosting: native A2aAgent wrapper Preview exposing an AgentCard and task store on Agent Runtime
  • Any language: custom Dockerfile or Artifact Registry image conforming to the runtime HTTP contract

SDK, agent-starter-pack & agents-cli

  • Agent Platform SDK: google-cloud-agentplatform exposes agentplatform.Client(project=…, location=…) with client.runtimes, client.sessions, client.sandboxes, and client.memory_banks (replacing legacy agent_engines).
  • agent-starter-pack & agents-cli: scaffolds production Terraform IaC, Cloud Build / GitHub Actions CI/CD with automated agents-cli eval regression gates, OpenTelemetry spans, and BigQuery feedback sinks.
  • Managed Agents API Preview: declarative Agents API + Skill Registry + stateful Interactions API running in an isolated Linux container with no network access by default.
Deployment methodLanguagesBest for

Common trap — reserved environment variables

Do not set platform-managed variables such as GOOGLE_CLOUD_PROJECT or PORT in your deployment config, and avoid the GOOGLE_CLOUD_AGENT_ENGINE prefix for custom variables (except documented flags like GOOGLE_CLOUD_AGENT_ENGINE_ENABLE_TELEMETRY=true).

Exam tip

Agent Runtime hosts stateful agent orchestrators, not standalone MCP tool servers. Deploy custom Streamable HTTP MCP servers on Cloud Run or GKE, register them in Agent Registry, and call them from your agent.

Common trap — "stateless Cloud Run remembers"

A Cloud Run instance can be replaced or scaled to zero at any moment. Conversation state kept in process RAM vanishes. Persist it in Agent Platform Sessions (--session_service_uri agentengine://<id>), Memorystore, Firestore, or Cloud SQL.

4. Context Engineering: Sessions, Memory Bank & Example Store

Production agents apply context engineering — assembling only relevant recent events, compacted summaries, scoped long-term user facts, and top-k dynamic examples per turn to prevent context rot and runaway token spend.

AbstractionScopeLifetime
SessionChronological append-only sequence of events (messages, thoughts, tool calls/outputs) for one interactionOne conversation (apply sliding-window compaction on long threads)
StateMutable key-value scratchpad attached to a session (temp:, session, user:, app: prefixes in ADK)Current turn or current conversation
Memory BankLLM-extracted, consolidated semantic facts & preferences about a user/entityPersistent across sessions (governed by TTL & revisions)

Sessions: ADK agents deployed to Agent Runtime get managed sessions automatically. Outside Agent Runtime (Cloud Run, GKE, local), point ADK at the managed service with --session_service_uri agentengine://<id>.

Memory Bank

  • Asynchronous LLM extraction & consolidation: GenerateMemories extracts durable facts from session events in the background and consolidates them with existing memories (merging duplicates, updating changed preferences, resolving contradictions).
  • Memory-as-a-tool: CreateMemory writes an explicit fact immediately when the agent decides to remember on command.
  • Scoped retrieval: RetrieveMemories fetches by scope or semantic similarity search against the active user turn.
  • Strict identity isolation: partitioned by an identity scope such as {user_id, app_name} — never share unscoped namespaces across users.
  • Governance controls: custom Memory Topics (defining what to extract and what PII to ignore), multimodal input, TTL policies, auditable memory revisions, IAM Conditions, roles roles/aiplatform.memoryViewer / roles/aiplatform.memoryEditor, CMEK, and regional residency (gcp.resourceLocations).
  • ADK integration: VertexAiMemoryBankService; trigger incremental extraction in callbacks via add_events_to_memory (preferred over full-session add_session_to_memory).

Common trap — persistent memory poisoning

Untrusted external tool outputs (emails, web pages, tickets) processed during memory extraction can plant malicious instructions into Memory Bank that replay across future sessions. Screen inputs with Model Armor, constrain Memory Topics, and audit memory revisions (Security guide).

Example Store Preview

Stores curated few-shot input→trajectory/output demonstrations and injects only the most semantically relevant ones dynamically at inference time. The embedding model (e.g., text-embedding-005, text-multilingual-embedding-002, or gemini-embedding-001) is immutable after instance creation; changing embedding models requires creating a new instance. Default quota: 50 instances per project per region.

NeedRight Component

5. Code Execution Sandbox

The Code Execution sandbox runs untrusted, model-generated Python inside an isolated container: sub-second startup/execution, file I/O up to 100 MB, and stateful sandbox files/variables persisting up to 14 days (configurable TTL). ADK's AgentEngineSandboxCodeExecutor binds one sandbox per session so DataFrames and generated charts carry across turns — and can be invoked even when your agent runs on Cloud Run or GKE. Similarly, the Managed Agents API Linux sandbox blocks outbound network egress by default while mounting approved Skill Registry assets.

Mental model — runtime vs. sandbox

The runtime executes trusted orchestration code you wrote and reviewed (holding IAM/MCP credentials). The sandbox executes untrusted code synthesized by the model at runtime. Never run LLM-generated code via exec() inside the agent's own container.

Common trap — over-provisioning the sandbox

Injecting service-account tokens or opening unrestricted internet egress inside a code sandbox defeats containment. Pass input data strictly as scoped files and read sanitized outputs back.

RAG Engine pipeline

Ingestion (local files, Cloud Storage, Google Drive, Slack/Jira connectors) → transformation (chunking via default parser, LLM parser, or Document AI Layout Parser) → embedding → corpus index → retrieval → generation. Vector store options depend on the deployment mode: Spanner mode offers RagManagedDb (default), Agent Retrieval, Vector Search 1.0, Pinecone, and Weaviate; Serverless mode defaults to an Agent Retrieval collection (Pinecone and Weaviate as alternatives). Both modes support VPC-SC; only Spanner mode supports CMEK.

Precision & citation verification

  • Ranking API (semantic-ranker-default@latest): stateless cross-encoder reranker applied to top-N candidates from any retriever.
  • Check Grounding API: scores claim-by-claim factual support against supplied context chunks to block hallucinations.
  • Grounding metadata: webSearchQueries, searchEntryPoint, groundingChunks, groundingSupports — render verifiable citations.
  • Agent Search grounding: attach up to 10 data stores per request; IAM roles roles/discoveryengine.viewer / editor.

ADK built-in retrieval tools: google_search (web grounding), VertexAiSearchTool (Agent Search data store), VertexAiRagRetrieval (RAG Engine corpus), VertexAiRagMemoryService (RAG-backed memory).

Google Cloud MCP servers & enterprise tool integrations

  • Google Cloud remote MCP servers: Google-hosted HTTP endpoints (https://<service>.googleapis.com/mcp or regional .rep.googleapis.com/mcp) that become available when you enable the service API and are registered in Agent Registry automatically, across BigQuery, Cloud SQL, AlloyDB, Spanner / Bigtable / Firestore / Memorystore, Cloud Storage, GKE, Cloud Run, Compute Engine, Pub/Sub, Cloud Logging / Monitoring / Trace, Apigee API hub, Knowledge Catalog, and Agent Retrieval Preview. Requires MCP Tool User (roles/mcp.toolUser → mcp.tools.call) plus underlying service IAM roles.
  • MCP Toolbox for Databases (github.com/googleapis/mcp-toolbox, formerly genai-toolbox): open-source MCP server that manages connection pools and auth, ships prebuilt tools per database (--prebuilt=<database>), and lets you define parameterized, SQL-injection-safe custom tools in tools.yaml for Cloud SQL, AlloyDB, Spanner, BigQuery, and many non-Google databases (PostgreSQL, MySQL, MongoDB, Neo4j, Snowflake and others).
  • Custom & SaaS MCP servers: host custom Streamable HTTP MCP servers on Cloud Run or GKE, or wrap enterprise ERPs/CRMs via Apigee and Application Integration (ApplicationIntegrationToolset); govern discovery in Agent Registry and egress via Agent Gateway (Security guide).

Common trap — wrong distance metric

When an Agent Retrieval / Vector Search index backs a RAG Engine corpus, configure the distance metric as COSINE. RAG Engine queries using cosine distance, so leaving the index at default DOT_PRODUCT fails with FAILED_PRECONDITION.

RAG Engine deployment modes

One RAG API routes to whichever mode the project has active; corpora created under the other mode stay stored but hidden until you switch back.

  • Serverless mode: no tier management, autoscales, and by default provisions an Agent Retrieval collection in your project as the vector database (Pinecone and Weaviate are alternatives; RagManagedDb is not offered). Storage is not isolated and CMEK is not supported.
  • Spanner mode (default when no mode is chosen): dedicated Spanner instance at the Basic tier (default, fixed low compute) or the Scaled tier (autoscaling, production volumes); the Unprovisioned tier deletes the instance and its data. Isolates storage and performance, supports CMEK, and offers RagManagedDb (default), Agent Retrieval, Vector Search 1.0, Pinecone, and Weaviate.
  • Both modes support VPC Service Controls.

When to choose and CMEK

  • Vector Search 1.0: existing pipelines with your own embedders and tuned, always-on ANN endpoints.
  • Agent Retrieval: a new custom agent store that keeps payload and vectors together, with auto-embeddings, keyword plus semantic search, and an MCP server.
  • RAG Engine Serverless mode: the fastest managed document RAG when CMEK is not required.
  • RAG Engine Spanner mode (or a CMEK-enabled Agent Retrieval collection): when policy demands CMEK or isolated storage and performance.
  • CMEK on Agent Retrieval: set the Cloud KMS key (same region as the collection) at Collection creation (--kms-key). An existing collection cannot be switched; export its Data Objects to Cloud Storage and import them into a new CMEK collection.

Anti-pattern: Serverless mode under a CMEK mandate

Serverless mode has no CMEK option, so a key-management policy rules it out. Pick Spanner mode before importing data, because corpora do not carry over between modes.

How Agent Registry records MCP servers

  • Google and Google Cloud servers register automatically when the API is enabled, tools included. The McpServer resource exists only in global; regional endpoints appear in its interfaces field, so query with --location=global (a regional query returns NOT_FOUND).
  • Custom servers on Cloud Run register automatically when deployed with gcloud beta run deploy --functional-type=mcp-server (services only; Cloud Run jobs can't be MCP servers). --identity-type (beta) selects agent-identity or service-account (default).
  • Custom servers on GKE register automatically from the registry.gke.io/functional-type: "MCP_SERVER" label plus modelcontextprotocol.info/* annotations; GKE fetches the tool spec from the running server.
  • External servers, and cross-project servers without a management boundary, need manual registration (gcloud agent-registry services create … --mcp-server-spec-type=tool-spec) with an uploaded toolspec.json (MCP tool schema, 10 KB max) listing tool names, descriptions, and annotations such as readOnlyHint or destructiveHint.
  • Data residency: register manually in a specific region when registry metadata must stay there. Role: registering requires roles/agentregistry.editor on the governance project.

Transports and identity choice

  • Transport: stdio runs the server as a local child process on the same machine (IDEs, CLIs, local Toolbox); Streamable HTTP over HTTPS is required for remote and production servers on Google infrastructure, Cloud Run, or GKE.
  • Identity: a service account or agent identity acts on the agent's own authority (recommended for production so permissions and logs are scoped to the agent); end-user OAuth runs and logs actions as the user, needed when downstream tools enforce per-user ACLs (brokered through Auth Manager).
  • Stateless MCP: Google Cloud remote servers support MCP version 2026-07-28, which drops the initialize handshake and Mcp-Session-Id; each request carries what it needs in HTTP headers or _meta, so load balancers route without parsing bodies.
  • Agent identity vs. service account: agent identities are SPIFFE-based, not shared across workloads by default, can't be impersonated, and don't allow long-lived keys.
  • Security controls (Agent Gateway egress policies, IAP tool-level authorization, Model Armor screening of MCP traffic) are covered in the Security guide.

Progressive disclosure through four ADK skill tools

  • list_skills shows the model only the catalog of skill names and descriptions.
  • load_skill pulls one skill's full instructions and tools into context.
  • load_skill_resource fetches a referenced file or asset on demand.
  • run_skill_script executes the skill's bundled code. Each tool is a point where a policy can return a verdict.

Compliance and runtime controls

  • Compliance: Access Transparency and US/EU data residency are supported; CMEK, VPC Service Controls, and HIPAA are not. Regions: us-central1, europe-west4, us-east5.
  • Tainted-session control: an NLC can deny load_skill for any skill that sends messages or writes externally once the history contains web, email, or uploaded content.
  • Supply-chain control: an NLC can inspect the arguments of an install tool triggered by skill instructions and deny packages outside an allowlist.
  • Caveat: semantic governance uses an LLM, so verdicts are probabilistic. Keep IAM and network egress controls as the deterministic layer.

Anti-pattern: registry admin roles on agents

Granting roles/agentregistry.admin or roles/agentregistry.editor to an agent identity lets a compromised agent alter tool definitions or enroll a malicious agent. On the standalone-skills path, give consuming agents roles/agentregistry.viewer and publishers or CI pipelines roles/agentregistry.user; on the Skill Registry path, use roles/aiplatform.viewer for consumers and roles/aiplatform.user for publishers.

Anti-pattern: IAM as the only skill control

IAM decides who may publish or read a package, but an authorized agent can still be steered by injected content into loading a powerful skill. Pair IAM with semantic governance policies.

Common trap — caching across permission boundaries

8. Optimize Part 1: Evaluation, 2-Step Simulation & Golden Flywheels

The Gen AI Evaluation Service (client.evals.evaluate() / agents-cli eval) grades both final response quality and multi-step tool trajectories.

Metric familyWhat it doesRepresentative metrics
Adaptive rubrics (recommended)Autorater dynamically generates prompt-specific pass/fail tests per eval case, then scores the agent response against themGENERAL_QUALITY
Static rubricsApplies fixed organization-wide pass/fail rules to every promptCustom brand tone / regulatory disclaimer rubrics
Agent & faithfulness metricsSpecialized LLM-as-judge autoraters for grounded agent turnsFINAL_RESPONSE_QUALITY, HALLUCINATION, TOOL_USE_QUALITY
Trajectory metricsDeterministically compares actual tool-call sequence/args against expected reference stepstrajectory_exact_match, trajectory_in_order_match, trajectory_any_order_match, precision/recall
Computation metricsFast, deterministic programmatic checksJSON Schema validation, SQL AST check, exact match, ROUGE/BLEU

2-Step Agent Simulation & Environment Simulation

  • Prerequisite: requires an immutable Agent Registry version snapshot so multi-turn experiments are reproducible.
  • 2-Step User Simulation: (1) inspects agent instructions & tool schemas to synthesize a Starting Prompt + hidden Conversation Plan (persona, goal, edge-case constraints); (2) runs a simulated user LLM across multi-turn sessions to produce full traces.
  • Environment Simulation: intercepts tool calls during evals to inject deterministic faults (HTTP 503, 429, timeout spikes, mocked edge-case payloads) without mutating live production APIs.

Online Monitors & Golden-Dataset Flywheel

  • Online Evaluation (OnlineEvaluator): continuously samples live production OpenTelemetry GenAI traces and runs async autoraters to alert on quality regressions.
  • Production-to-Golden Flywheel: export thumbs-down user feedback, HITL escalations, and low-scoring online traces to BigQuery → redact PII via Sensitive Data Protection (SDP) → curate expected trajectories → append to the CI/CD golden regression suite (agents-cli eval).

Exam tip

Final-answer metrics alone miss "right answer, wrong path" compliance bugs (e.g., issuing a refund without calling verify_eligibility first). Always pair outcome rubrics with trajectory metrics (trajectory_in_order_match / trajectory_exact_match) when tool ordering matters.

Common trap — over-permissive online monitors

Online evaluation monitors run under a platform service agent with access to trace payloads and judge quota; restrict IAM permissions to create or edit monitors to prevent unauthorized trace inspection.

9. Optimize Part 2: Observability, Audit & Prompt Optimization

OpenTelemetry & 8 Agent Registry Views

  • Telemetry flags: set GOOGLE_CLOUD_AGENT_ENGINE_ENABLE_TELEMETRY=true (exports traces, metrics, and logs without raw prompt text) + OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental. Raw payload capture is opt-in: set OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=EVENT_ONLY and keep ADK_CAPTURE_MESSAGE_CONTENT_IN_SPANS=false (the value true is invalid with the latest conventions and collects nothing), paired with SDP de-identification and restricted log buckets (roles/logging.privateLogViewer).
  • 8 Agent Registry Observability tabs: Overview, Evaluation, Models, Tools (per-tool & per-MCP-server p95 latency + "no-tool interactions"), Usage, Logs, Traces (waterfall/DAG), and Topology (live graph of agents, A2A peers, models, and MCP servers) + native Model Armor spans.

Dual-Attribution Audit, Failure Clusters & Optimizer

  • Dual-Attribution Cloud Audit Logs (is_agentic=true): records both the cryptographic SPIFFE Agent Identity and the initiating human user principal to eliminate confused-deputy audit blind spots.
  • Failure Cluster Analysis: automatically groups failing simulation and production traces into root-cause clusters (e.g., ambiguous tool arg schemas, premature loop exits).
  • Prompt Optimization (Agent Optimizer): closed-loop programmatic optimizer that mutates system prompts/examples and validates candidates against your golden evalset via client.evals before rollout.
Production SymptomFirst Diagnostic View & Fix
Slow p95 turn responsesTraces waterfall → check whether thinking_level=HIGH decode, serial MCP calls, or retrieval dominates
Agent hallucinates instead of calling a toolTools tab ("no-tool interactions") → sharpen tool docstring/schema + add trajectory eval
Recurring errors or quality drop after model migrationFailure Cluster Analysis + Evaluation tab → run programmatic Prompt Optimization against golden evals
Unexpected token spend spikeModels / Usage tabs → compact long session histories and align static prompt prefixes for implicit caching

Common trap — logging raw prompts by default

Setting OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=EVENT_ONLY writes raw user prompts and tool payloads into logs, risking PII exposure. Keep content capture disabled by default or pair it with SDP de-identification and restricted log buckets (Security guide).

10. Cost, Quotas & Capacity

Error / situationMeaningArchitectural fix
429 RESOURCE_EXHAUSTED on Standard PayGoShared regional pool contention or project TPM/QPM quota exceededRoute stateless calls to the global endpoint, use exponential backoff with jitter, enable Priority PayGo for critical bursts, or reserve Provisioned Throughput (GSUs; spills over to PayGo by default unless X-Vertex-AI-LLM-Request-Type: dedicated is set)
"Region temporarily at capacity" deploying to Agent RuntimePhysical regional compute pool saturation — not a project quota capDeploy to an alternate region, request smaller per-instance CPU/memory, or retry off-peak

Agent Runtime representative default quotas (per project per region; verify current docs): query/streamQuery 90/min, session writes 100/min, append events 300/min, session reads 10,000/min, max 100 agent resources, Memory Bank writes 100/min and reads 300/min, sandbox executions 1,000/min.

Six FinOps levers: (1) tiered routing (3.5 Flash-Lite → 3.8 Flash → 4 Argon); (2) right-size thinking_level; (3) byte-identical static prompt prefixes for zero-storage-cost implicit caching; (4) session compaction & tool-output masking; (5) right-size min_instances and undeploy idle Vector Search 1.0 endpoints; (6) sample 1–5% of live traffic for OnlineEvaluator and run bulk offline evals on Flex PayGo or Batch inference.

Common trap — quota increase for a capacity error

Filing an IAM/project quota increase ticket will never resolve "Region temporarily at capacity". Switch region, reduce instance sizing, or retry instead.

12. Glossary, Related Guides & Practice Quiz

Agent Runtime
Managed stateful agent hosting (formerly Agent Engine); API resource reasoningEngines.
Managed Agents API Preview
Declarative Agents API + Skill Registry + stateful Interactions API with an isolated no-egress Linux sandbox.
Session / Event / State
One conversation, its ordered event log, and its mutable key-value scratchpad.
Memory Bank
Async LLM-extracted, consolidated, user-scoped long-term memory with TTL & revisions.
Example Store Preview
Dynamic few-shot trajectory/example retrieval (embedding model locked at creation).
Code Execution sandbox
Sub-second isolated Python container (100 MB I/O, up to 14-day TTL) for untrusted generated code.
Agent Search vs. RAG Engine
Turnkey connector + native-ACL enterprise search vs. code-first modular corpus RAG pipeline.
2-Step & Environment Simulation
Multi-turn user simulator (Starting Prompt + Conversation Plan) and deterministic tool-fault injector.
Dual-Attribution Audit Log
Cloud Audit Log (is_agentic=true) recording both SPIFFE Agent Identity and human principal.
Failure Clusters & Agent Optimizer
Root-cause clustering of failed traces paired with automated closed-loop prompt optimization.
Provisioned Throughput
Reserved model capacity bought in GSUs for predictable latency & throughput.
Google Cloud remote MCP server
Google-hosted HTTPS MCP endpoint for a Cloud service, enabled with the service API, auto-registered in Agent Registry, and gated by roles/mcp.toolUser plus resource IAM.
MCP Toolbox for Databases
Open-source MCP server (googleapis/mcp-toolbox) with prebuilt database tools and parameterized custom tools defined in tools.yaml.
toolspec.json
Tool specification file (MCP tool schema, 10 KB max) uploaded when manually registering an external MCP server in Agent Registry.
Streamable HTTP vs. stdio
Remote HTTPS MCP transport for cloud servers vs. local child-process transport for servers on the same machine.
ADK session services
VertexAiSessionService (managed Agent Platform Sessions), DatabaseSessionService (SQL database you operate), and InMemorySessionService (non-persistent process memory).
Skill Registry Preview
Agent Platform repository that validates, versions, and serves SKILL.md-based skill packages; inherits project IAM (roles/aiplatform.*).
Skill revision
Immutable snapshot of one version of a skill; agents load the default revision unless a specific revision is requested.
gcp-skill-registry
Google-managed built-in skill that lets an agent create, search, and manage skills in Skill Registry.
Semantic governance policy Preview
LLM-evaluated natural language constraint that can allow or deny skill tool calls such as load_skill and run_skill_script.
RAG Engine Serverless vs. Spanner mode
Zero-tier, autoscaled backend without CMEK vs. dedicated Spanner instance with Basic or Scaled tiers, isolation, and CMEK.
Collection / Data Object
Agent Retrieval container with a schema (similar to a table) and the individual JSON record it stores alongside its vector fields.
Semantic cache
Vector-indexed response cache (for example Memorystore for Redis vector search) serving stored answers to semantically similar prompts; partition keys by tenant or ACL scope.
